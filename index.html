1. O que é o GitHub?

O GitHub é a maior plataforma de hospedagem de código-fonte do mundo, baseada no sistema de controle de versões Git. Ele permite que desenvolvedores armazenem, versionem, colaborem e revisem código de forma organizada e eficiente, sendo usado tanto por projetos pessoais quanto por grandes empresas. O Git foi criado em 2005 por Linus Torvalds para solucionar o problema de versionamento e correção de códigos.

Além de hospedar repositórios, o GitHub oferece ferramentas integradas como Issues (gestão de tarefas), Pull Requests (revisão de código), GitHub Actions (CI/CD automatizado), GitHub Pages (hospedagem de sites estáticos) e GitHub Copilot (assistente de IA para código).

2. Configuração da Máquina Local

2.1 Instalando o Git

Windows

# Baixe o instalador em: https://git-scm.com/download/win
# Execute e mantenha as opções padrão

macOS

brew install git

Linux (Ubuntu/Debian)

sudo apt update && sudo apt install git -y

2.2 Configurando sua Identidade

Essas informações aparecem em todos os seus commits e são obrigatórias:

git config --global user.name "Seu Nome Completo"
git config --global user.email "seu@email.com"

Para conferir as configurações salvas:

git config --list

2.3 Configurando Chave SSH

A chave SSH permite autenticação segura sem precisar digitar usuário e senha a cada operação. É a forma recomendada de trabalhar com o GitHub.

Passo 1 -- Verificar se já existe uma chave

ls ~/.ssh
# Se aparecer id_ed25519 e id_ed25519.pub, você já tem uma chave -- pule para o Passo 3

Passo 2 -- Gerar a chave

ssh-keygen -t ed25519 -C "seu@email.com"
# Pressione Enter para aceitar o caminho padrão
# Defina uma senha ou deixe vazio (só pressione Enter)

Passo 3 -- Iniciar o agente e adicionar a chave

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

Passo 4 -- Copiar a chave pública

# Linux / macOS
cat ~/.ssh/id_ed25519.pub

# Windows (PowerShell)
Get-Content ~/.ssh/id_ed25519.pub

# Selecione e copie tudo -- começa com: ssh-ed25519 AAAA...

Passo 5 -- Adicionar ao GitHub

  • Acesse github.com e faça login.
  • Clique no avatar (canto superior direito) > Settings.
  • Menu lateral: SSH and GPG keys > New SSH key.
  • Cole a chave no campo Key, defina um título e clique em Add SSH key.

Passo 6 -- Testar a conexão

ssh -T git@github.com
# Resposta esperada: Hi seu_usuario! You've successfully authenticated...
# Dica: Se aparecer uma pergunta sobre fingerprint, digite yes e pressione Enter.

3. Criando um Repositório no GitHub

3.1 Criando via Interface Web

Siga os passos abaixo para criar um novo repositório:

  1. Acesse github.com e clique no botão + > New repository (ou botão verde New).
  2. Preencha o Repository name com um nome claro e descritivo.
  3. Adicione uma Description explicando o propósito do projeto.
  4. Escolha a visibilidade: Pública (qualquer pessoa vê) ou Privado (só você e convidados).
  5. Marque Add a README file para inicializar o repositório.
  6. Opcionalmente selecione um .gitignore para sua linguagem e uma licença.
  7. Clique em Create repository.

3.2 Tipos de Visibilidade

Visibilidade Descrição
Public Qualquer pessoa pode ver e clonar. Ideal para projetos open source.
Private Apenas você e colaboradores adicionados podem acessar.
Internal Visível para todos os membros da organização (apenas planos Enterprise).

3.3 Conectando um Projeto Local Existente ao GitHub

Se você já tem um projeto na sua máquina e quer subi-lo para o GitHub:

# 1. Entre na pasta do projeto
cd meu-projeto
# 2. Inicialize o repositório local
git init
# 3. Adicione todos os arquivos
git add .
# 4. Faça o primeiro commit
git commit -m "feat: commit inicial"
# 5. Renomeie a branch para 'main'
git branch -M main
# 6. Conecte ao repositório remoto
git remote add origin git@github.com:seu_usuario/nome-do-repo.git
# 7. Envie para o GitHub
git push -u origin main

3.4 Clonando um Repositório Existente

# Via SSH (recomendado -- requer chave SSH configurada)
git clone git@github.com:usuario/nome-do-repo.git
# Via HTTPS
git clone https://github.com/usuario/nome-do-repo.git
# Entrar na pasta
cd nome-do-repo

4. Trabalhando com Branches

Branches (ramificações) permitem desenvolver funcionalidades ou corrigir bugs de forma isolada, sem interferir no código principal. No GitHub, a branch principal normalmente se chama main.

4.1 Comandos Essenciais de Branch

# Ver todas as branches (local e remota)
git branch -a
# Criar uma nova branch
git branch feature/minha-funcionalidade
# Criar e já trocar para a nova branch
git checkout -b feature/minha-funcionalidade
# Forma moderna (Git 2.23+)
git switch -c feature/minha-funcionalidade
# Trocar de branch
git checkout main
# Enviar branch para o GitHub
git push --set-upstream origin feature/minha-funcionalidade
# Deletar branch local
git branch -d feature/minha-funcionalidade
# Deletar branch remota
git push origin --delete feature/minha-funcionalidade

4.2 Convenção de Nomes para Branches

Prefixo Uso Exemplo
feature/ Nova funcionalidade feature/autenticacao-google
fix/ Correção de bug fix/erro-no-cadastro
hotfix/ Correção urgente em produção hotfix/falha-critica-pagamento
release/ Preparação de nova versão release/v2.0.0
docs/ Documentação docs/atualizar-readme
chore/ Manutenção e infra chore/atualizar-dependencias

5. Realizando Commits

Um commit é um registro permanente das mudanças feitas no código. Bons commits são atômicos (fazem uma coisa só) e possuem mensagens claras que explicam o que e por que foi feito.

5.1 O Ciclo Completo de um Commit

# 1. Ver o que foi modificado
git status
# 2. Ver as diferenças detalhadas
git diff
# 3. Adicionar arquivos ao staging
git add nome-do-arquivo.js
# arquivo específico
git add src/
# pasta inteira
git add .
# 4. Revisar o que será commitado
git diff --staged
# 5. Criar o commit
git commit -m "feat: adiciona validação de CPF no cadastro"
# 6. Enviar para o GitHub
git push origin feature/minha-branch

5.2 Padrão Conventional Commits

Um padrão amplamente adotado para mensagens semânticas e legíveis:

Tipo Quando usar Exemplo
feat:Nova funcionalidadefeat: adiciona login com Google
fix:Correção de bugfix: corrige erro 500 no endpoint de usuários
docs:Documentaçãodocs: atualiza README com instruções de deploy
style:Formatação sem mudança de lógicastyle: aplica prettier no projeto
refactor:Refatoraçãorefactor: extrai lógica de autenticação para serviço
test:Testestest: adiciona testes para o serviço de email
chore:Manutençãochore: atualiza dependências do projeto
perf:Performanceperf: otimiza consulta SQL do relatório

5.3 Comandos Úteis

# Alterar a mensagem do último commit (antes do push)
git commit --amend -m "nova mensagem corrigida"
# Histórico compacto e visual
git log --oneline --graph
# Desfaz o último commit mantendo as alterações
git reset --soft HEAD~1
# Reverte um commit de forma segura (cria novo commit)
git revert <hash-do-commit>
Atenção: Nunca use git reset --hard em branches compartilhadas com o time -- isso reescreve o histórico e causa conflitos.

6. Sincronizando com o GitHub

Manter o repositório local atualizado com o remoto é essencial para evitar conflitos ao trabalhar em equipe.

6.1 Comandos de Sincronização

# Baixar as mudanças sem aplicar (seguro para inspecionar antes)
git fetch origin
# Baixar e aplicar as mudanças na branch atual
git pull origin main
# Enviar seus commits para o GitHub
git push origin feature/minha-branch
# Ver os repositórios remotos configurados
git remote -v
# Alterar a URL do repositório remoto
git remote set-url origin git@github.com:usuario/novo-repo.git
Dica: Sempre faça git pull antes de começar a trabalhar para garantir que você está na versão mais recente.

6.2 Tabela de Comandos de Sincronização

Comando O que faz

git pull origin mainBaixa e aplica as mudanças na branch atual
git push origin <branch>Envia seus commits locais para o GitHub
git push -u origin mainEnviar e vincula a branch local com a remota

7. Realizando um Pull Request (PR)

O Pull Request é o processo formal de propor que suas alterações sejam revisadas e incorporadas a outra branch. É o coração da colaboração no GitHub.

7.1 Criando um Pull Request

  1. Faça push da sua branch: git push origin feature/minha-branch
  2. Acesse o repositório no GitHub.
  3. Uma faixa amarela aparecerá sugerindo criar um PR - clique em Compare & pull request.
  4. Ou vá em Pull requests > New pull request e selecione as branches.
  5. Defina: base (destino, geralmente main) e compare (sua branch com as alterações).
  6. Preencha o título e a descrição detalhada.
  7. Adicione Reviewers (revisores), Labels e Milestone se necessário.
  8. Clique em Create pull request.

7.2 Boas Práticas para Descrição de PR

## O que foi feito: descreva claramente a mudança realizada.
## Por que: explique por que essa mudança é necessária.

7.3 Revisando um Pull Request

  • Acesse a aba Files changed para ver todas as diferenças linha a linha.
  • Clique em uma linha específica para adicionar comentário.
  • Use o botão Review changes para submeter sua revisão.
  • Approve - aprovar as mudanças para merge.
  • Comment - deixar comentários gerais sem aprovar ou rejeitar.
  • Request changes - solicita alterações antes do merge.

7.4 Opções de Merge

Opção de Merge O que faz
Create a merge commitCria um commit de merge. Preserva todo o histórico da branch. Ideal para features.
Squash and mergeUne todos os commits em um único antes de mesclar. Histórico mais limpo.
Rebase and mergeReaplica os commits sobre a base de forma linear. Sem commit de merge.

Dica: marque sempre 'Delete branch' após o merge para manter o repositório organizado.

8. Fork e Contribuindo com Projetos de Terceiros

Para contribuir com um repositório que não é seu, o fluxo utiliza Fork - uma cópia do repositório original na sua conta do GitHub - pois você não tem permissão de escrita no repositório original.

8.1 Fluxo Completo de Contribuição

  1. Acesse o repositório original e clique em Fork (canto superior direito).
  2. Clone o SEU fork (não o original).
git clone git@github.com:SEU_USUARIO/nome-do-repo.git
cd nome-do-repo
  1. Adicione o repositório original como upstream.
git remote add upstream git@github.com:DONO_ORIGINAL/nome-do-repo.git
git remote -v
# origin = seu fork | upstream = original
  1. Crie uma branch para suas alterações.
git checkout -b fix/corrige-bug-no-formulario
  1. Faça as alterações, commit e push para o seu fork.
git add .
git commit -m "fix: corrige validação no formulário de contato"
git push origin fix/corrige-bug-no-formulario
  1. No GitHub, abra um Pull Request do seu fork para o repositório original.

8.2 Mantendo o Fork Atualizado

Quando o projeto original receber novas atualizações, sincronize seu fork:

git fetch upstream
git checkout main
git merge upstream/main
git push origin main
